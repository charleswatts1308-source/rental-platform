RELEASE 2 — DELIVERY-EVENT CAPTURE  (feature/delivery-events)
====================================================================

TEMPORARY. The point is to see the bytes Mailgun actually sends, so the
real receiver is built against observed payloads rather than
documentation. It comes back off afterwards.

Do NOT start this until Release 1 is tested and the ledger updated.

WHY IT EXISTS
  The D0 found that our existing signature middleware reads FLAT
  timestamp/token/signature fields (the inbound-routing shape).
  Delivery events are believed to NEST those under a "signature"
  object — which would make the middleware reject every event with a
  406, and 406 is the response Mailgun treats as "stop retrying". So
  events would be discarded permanently and silently while the webhook
  looked healthy. This run settles that from evidence.

DEPLOY
[ ] Choose a long random token (password generator). Call it TOKEN.
[ ] Add to prod .env:   MAILGUN_CAPTURE_TOKEN=TOKEN
[ ] While in the .env, check for duplicate KEY= lines — within one
    file Laravel takes the LAST and silently ignores earlier ones.
    That is the trap that broke the allowlist before.
[ ] git push origin feature/delivery-events:master
[ ] Plesk: pull/deploy
[ ] php artisan config:cache      (prod caches config; without this
                                   the token is not read and the
                                   endpoint stays 404)
[ ] Confirm inert-when-off works as expected: the endpoint 404s for
    any wrong token.

MAILGUN
[ ] Webhooks -> DOMAIN-LEVEL tab -> mg.renters.rent -> Add webhook
    URL: https://renters.rent/webhooks/mailgun/capture/TOKEN
[ ] Subscribe: Delivered, Permanent Fail, Temporary Fail, Complained
[ ] DOMAIN-level, NOT account-level. Account-level fires for every
    domain including the gafol sandbox, and case_message ids are plain
    integers — a staging event could match a production message and
    stamp a delivery status onto the wrong case's record.

THE TWO SENDS
[ ] Raise a case with a landlord address at a domain that cannot
    exist, e.g. landlord@this-domain-does-not-exist-9f3k2.com
    -> should produce a permanent_fail event
[ ] Raise a second case to an inbox you control
    -> should produce a delivered event

COLLECT
[ ] Fetch storage/logs/mailgun-capture.log (Plesk File Manager or
    FileZilla) and send it over
[ ] TREAT AS PERSONAL DATA — it contains real recipient addresses and
    subject lines. Fetch it, do not leave it on the box.

TEAR DOWN — do not skip
[ ] Delete the webhook in Mailgun
[ ] Remove MAILGUN_CAPTURE_TOKEN from prod .env
[ ] php artisan config:cache
[ ] Delete storage/logs/mailgun-capture.log from the box
[ ] Redeploy main to master so prod is back on released code

WHAT WE LEARN
  If the payload shows a NESTED signature object, the D0 was right and
  a second middleware is confirmed necessary.
  If the fields are FLAT after all, the existing middleware can be
  reused and the D0's central finding was wrong — equally worth
  knowing, and cheaper.
